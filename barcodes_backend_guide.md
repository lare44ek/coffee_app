# Гайд для бэкенда: подключение штрих-кодов (barcode) в Effoc

Это инструкция для того, кто держит сервер и БД. Цель: чтобы в приложении
заработал сканер — навёл камеру на штрих-код товара → приложение нашло товар и
подставило его в маркировку.

---

## 0. Как это работает (коротко)

- На клиенте (Flutter) уже всё готово: модель `Product` получила поле `barcode`,
  `ApiService` читает и отправляет его, а экран сканера ищет товар.
- **Поиск товара по коду происходит на клиенте**, по списку из `GET /products`.
  Поэтому **отдельный эндпоинт для сканирования НЕ нужен**. Достаточно, чтобы:
  1) в БД у товаров были штрих-коды, 2) `GET /products` возвращал поле `barcode`,
  3) `POST/PUT /products` принимали `barcode` (для будущего редактирования).

Контракт клиента (что он ждёт от API) — см. раздел 3.

---

## 1. Шаг 1 — добавить колонку `barcode` в таблицу `products`

```sql
ALTER TABLE products ADD COLUMN barcode VARCHAR(32) NULL UNIQUE;
```

Почему так:
- `VARCHAR`, **не число** — у EAN-13 важны ведущие нули и длина (13 знаков).
- `NULL` — у части товаров кода может не быть.
- `UNIQUE` — один код = один товар (защита от дублей при заливке).
- Хранить **только цифры, без пробелов и дефисов**: `'4650139140212'`.

---

## 2. Шаг 2 — залить коды (`barcodes_import.sql`)

Файл лежит рядом. **Запускать по блокам, не вслепую.**

- **Блок 1 — `UPDATE`** для товаров, которые уже есть в каталоге. Сопоставление
  идёт по `products.name` (имена взяты из `lib/models/catalog.dart`).
  ⚠️ Перед запуском убедись, что имена в БД **точно совпадают** с теми, что в
  `WHERE name='...'`. Если в БД имена другие — поправь `WHERE` или привяжи по `id`.
- **Блок 2 — `INSERT`** новых товаров.
  ⚠️ У 5 позиций `shelf_life_hours = 0` (нет срока в документе):
  Корица молотая Kotanyi, Солёная карамель мельница, Апельсиновый сок,
  Ванильный сахар, Тоник. **Проставь реальный срок после вскрытия (в ЧАСАХ)** —
  иначе маркировка для них посчитается неверно (expiry = момент вскрытия).
- **Блок 3 — `INSERT`** основ (бывшие «КЬЮ») и молока кокос/миндаль как
  отдельных товаров (по одному коду на товар).
- **В конце — закомментированные `DELETE`** старых «общих» строк
  (`Основа Q ...`, `Молоко кокосовое/миндальное 5yes`). Раскомментируй и выполни
  **только если** такие строки есть в БД и на них **нет ссылок** в `openings` /
  `inventory_events` / `stock` (иначе сломаешь внешние ключи). Если сомневаешься —
  не удаляй, просто оставь, дубль не критичен.

Справочник перевода сроков в часы (как уже закодировано в проекте):
`72 ч`, `96 ч`, `168 ч` (7 сут), `720 ч` (30 сут), `2160 ч` (90 сут),
`8760 ч` (12 мес), `13140 ч` (18 мес).

## 3. Шаг 3 — отдавать и принимать `barcode` в API

### GET /products
Каждый товар в ответе должен содержать `barcode` (может быть `null`).
Клиент парсит именно такие ключи (snake_case):

```json
[
  {
    "id": 12,
    "name": "Сироп ванильный",
    "shelf_life_hours": 2160,
    "category": "Сиропы и топпинги",
    "barcode": "4650139140212"
  },
  {
    "id": 13,
    "name": "Вода минеральная Jevea",
    "shelf_life_hours": 72,
    "category": "Сыпучие и прочее",
    "barcode": null
  }
]
```

### POST /products  и  PUT /products/:id
Тело запроса от клиента теперь содержит `barcode`:

```json
{
  "name": "Сироп лимон",
  "category": "Сиропы и топпинги",
  "shelf_life_hours": 2160,
  "min_stock": 0,
  "barcode": "4650139141493"
}
```

- Сохраняй `barcode` (может прийти `null`).
- `POST` по-прежнему возвращает `{"id": <int>}`.
- Желательно обрабатывать конфликт `UNIQUE` (код уже занят) и возвращать
  понятную ошибку (например 409), а не 500.

> Эндпоинты `/stock`, `/markings` менять не нужно — там `barcode` не используется.

## 4. Шаг 4 — проверка

1. БД: `SELECT name, barcode FROM products WHERE barcode IS NOT NULL;` — должны
   появиться коды.
2. API:
   ```
   curl https://api.mango-kokos.ru/products
   ```
   У товаров есть поле `barcode`.
3. Приложение: экран **«Маркировка»** → иконка сканера в шапке → навести на
   штрих-код товара. Товар должен подставиться в выбор, дальше «Вскрыто».
   Если код не в базе — приложение покажет «Код … не привязан к продукту».

> Если список товаров кэшируется на клиенте — после заливки кодов потяни
> обновление в приложении (перезайти / pull-to-refresh), провайдер перечитает
> `GET /products`.

---

## 5. Грабли (частые ошибки)

- Колонка `barcode` сделана числом → теряются ведущие нули. Только `VARCHAR`.
- В код попали пробелы/дефисы → точное сравнение на клиенте не сработает.
  Храни только цифры.
- Срок хранится в **часах** (`shelf_life_hours`), не в днях.
- Имена в `UPDATE` не совпали с БД → код просто не привяжется (0 rows affected).
  Проверяй `SELECT ... WHERE name='...'` заранее.
